current source template before it creates a flyer, detects newly uploaded and
revised templates, explains structural and capacity problems in Slack, reloads

frontier visual gate over Google's rendered pixels second, and no delivery when

## Technology decision

Gable should not reconstruct a native Slides template from a screenshot. Google
already returns each editable element's size, affine transform, object identity,
and page order. Those values are exact mutation targets and preserve editability;
raster inference would throw them away. Group-relative transforms are composed,
and rotated, mirrored, or ambiguous fillable geometry is refused rather than
measured as though it were ordinary.

Google's references define page-element size and transform data, z-order through
page-element ordering, and batch mutation semantics: [Page elements](https://developers.google.com/workspace/slides/api/reference/rest/v1/presentations.pages/pageElements),
[transform concepts](https://developers.google.com/workspace/slides/api/concepts/transforms),
and [Slides requests](https://developers.google.com/workspace/slides/api/reference/rest/v1/presentations/request).

The configured visual and conversational model is `gpt-5.6-sol`, OpenAI's
current flagship tier. It supports original-detail image input, structured
output, reasoning, and function calls. The current guidance recommends the
Responses API for reasoning and tool workflows: [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)
and [latest-model guidance](https://developers.openai.com/api/docs/guides/latest-model).

The resulting division of labor is deliberate:

1. Slides source objects provide exact dimensions, transforms, identity, and
   layer position.
2. Deterministic code resolves fields, predicts fit conservatively, verifies
   source values after mutation, and rejects foreign sample contact data.
3. GPT-5.6 Sol sees both the preserved human photo and the original-detail
   Google render, then judges clipping, collision, crop damage, distortion, and
   property fidelity through a strict fail-closed schema.
4. GPT Image 2 is used only when a supplied real photograph requires more than
   2x enlargement. It receives the exact fitted composition and its result must
   pass a composition-distance check. [GPT Image 2](https://developers.openai.com/api/docs/models/gpt-image-2)

Gemini image understanding and Document AI layout parsing were considered. They
are sensible independent evaluators for raster documents, but they do not beat
the editable Slides object graph as the primary measurement source. A second
model should be added only after a representative evaluation proves that its
independent catches outweigh extra cost, latency, and disagreement.

## Template and listing triage

Before copying a source, `slides/preflight.py` now checks:

- one native Slides page with measurable dimensions;
- one unambiguous hero frame and its exact target pixels;
- fillable text in ordinary, safely measurable boxes;
- required listing values before a copy exists;
- unknown tokens and field-like sample labels, including bare labels such as
  `MLS NUMBER`;
- standalone replacement literals, so substring replacement cannot corrupt
  surrounding copy;
- actual name, address, email, phone, price, and other listing text against the
  source box's width, height, type size, line policy, and 8-point floor;
- the supplied photo's crop loss and enlargement requirement against the
  measured frame; and
- a usable filed headshot when the source design has a headshot slot.

Structural or unreadable findings cannot be overridden. A readable but tight
text or crop warning pauses with two explicit paths: run the current design as
is, or update the source and ask Gable to check again. “Yes, run again” always
reloads the Drive source; it never trusts an older ready verdict.

The poller watches `Templates / Generic Templates`:

- The first scan adopts existing files silently.
- A later file is checked once, and a changed `modifiedTime` invalidates its
  earlier result and triggers a new review.
- Unsupported PowerPoint files and duplicate source names are named and
  refused; Gable never selects the convenient one.
- Deterministic success is followed by a placeholder-aware visual inspection
  of the source design.
- The verdict is persisted before Slack delivery. If Slack is unavailable, the
  stored message is retried without repeating the paid visual call.
- A removed source revokes an older ready audit.
- The source's owned thread supports another update-and-recheck cycle.

Every explicit mention, thread reply, photo upload, flyer edit, and template
recheck starts `assistant.threads.setStatus` immediately. The status follows the
timed personality sequence, changes to the real stage after six seconds, and is
cleared on every success or failure exit. The automatic form poll has no user
message to attach it to, so it correctly has no native waiting state.

## Render and photo fidelity

The supplied upload remains untouched. It keeps its aspect ratio until the
source frame is known and is then fitted once. Normal enlargement through 2x is
local; a larger source deficit gets at most one spend- and policy-gated Image 2
edit, then falls back to a truthful local resize if the provider or fidelity
check fails.

Hero and headshot replacements now preserve the source composition's original
layer boundary. A newly created image begins frontmost, so Gable identifies the
elements that originally sat above the deleted frame and brings only that set
back to the front in its original relative order. It no longer sends every hero
to the very back or leaves every headshot at the very front. Headshots are
fitted once to their own measured frame before publishing, instead of relying
on Slides to fit an arbitrary source aspect ratio.

Source images above 50 million pixels and provider outputs above the byte limit
are refused before expensive decompression. Every hosted derivative is verified
anonymously before its URL reaches Slides.

After fill and placement, Gable reads the slide back, verifies every value it
supplied, rejects known sample identities and foreign contact details, renders
Google's actual pixels, and requires a complete, confident, positive Sol
inspection. Failed, refused, malformed, incomplete, or inconclusive inspection
cannot become delivery.

## Live verification

The live checks were deliberately bounded: no response-Sheet write, no Slack
post, no finished design publication, and no deployment.

1. `tools/template_smoke_test.py --source Sold` copied the current `Sold`
   source under a unique smoke-test name in Generic Templates.
2. A temporary SQLite database adopted the existing folder and ran the same
   new-file scanner used by production.
3. Exactly one new file was reviewed. It entered `needs_template` because its
   address section measured roughly 34 average characters against the safe
   52-character certification target.
4. Cleanup moved only the temporary copy to Drive trash and confirmed that no
   active smoke-test copy remained.
5. The live Sol visual payload, strict schema, original image detail, thumbnail
   download, and spend guard were exercised successfully against the source.
6. After the conversation migration, a live Responses call answered the domain
   question normally, and a second call routed “Update the image” to
   `ask_clarifying`, specifically asking whether Chase meant the hero or the
   headshot.

The smoke result is a successful test of the triage path, not certification of
the `Sold` design. It correctly found a capacity issue and stopped.

## Bugs fixed during this audit

### User-facing and model routing

- Added the `/gable` status, run, retry, templates, pause, and resume handlers
  that the runtime contract described but the Bolt app did not register.
- Moved mutating command work to a bounded queue on the poller's owning thread;
  retries and rechecks now follow a successful source refresh rather than racing
  a Slack worker against the shared Google and SQLite clients.
- Migrated conversational function routing from Chat Completions to Responses.
  A live test proved Sol rejected the former endpoint's default reasoning plus
  function-tool combination, so every ordinary modeled Slack request had been
  failing.
- Raised the conversation-call reservation from the obsolete mini-model penny
  to ten cents; Sol's configured output ceiling alone could exceed the former
  reservation, making the hard cumulative budget optimistic.
- Replaced the misleading provider-error path that could blame Google Slides
  for an OpenAI conversation failure.
- Made explicit template-update and run-anyway phrases deterministic while
  leaving vague “try again” wording as a clarification rather than a guess.
- Enforced exactly Carmen and Chase's stable Slack IDs for mentions, replies,
  photos, and commands; channel membership alone is no longer authorization.
- Removed unused Slack scopes and stale OAuth configuration that could change
  SDK behavior.
- Kept the native waiting state alive until the actual question or outcome is
  posted, with cleanup on exceptions.

### Templates, fields, and layout

- Added current-source preflight before any Drive copy.
- Made template approval revision-specific and rechecked changed sources.
- Persisted template notices before Slack posting to prevent repeated paid
  visual calls after a messaging outage.
- Revoked ready state when a source is removed.
- Rejected rotated, mirrored, grouped-fillable, and ambiguous geometry instead
  of applying incorrect absolute measurements.
- Detected field-like bare sample labels that are not yet supported.
- Fixed combined office-and-cell phone labels after whitespace normalization.
- Matched long testimonial sample text before the short-field filter discarded
  it.
- Replaced identity comparison with value equality instead of object identity.
- Restored hero and headshot replacements to the source frame's layer boundary.
- Fitted headshots to their exact measured frame and verified them during
  preflight.
- Kept two-agent requests fail closed until templates identify role-specific
  text and portrait objects.
- Made failed readback, failed headshot placement, absent visual review,
  contradictory model output, malformed booleans, refusals, and incomplete
  Responses output block delivery.
- Joined split Responses text chunks before parsing them.
- Included public-fact research notes in the actual final or review Slack
  message instead of leaving them only in an internal result object.

### Photos

- Removed the initial 4:5 crop that caused a second destructive crop when the
  true source frame was wide.
- Distinguished exact fit, local enlargement, and model enlargement so Slack
  says “resized” unless a model derivative was actually used.
- Cleared stale `ai_enhanced` state before each refit and records it only after
  the accepted derivative is published and verified.
- Added source-pixel and provider-output memory bounds for the 1 GB runtime.
- Kept one paid image edit per listing and the shared $50 ceiling.
- Removed raw HTTP details from user-facing photo failures.

### State, data, and operations

- Split the oversized database store while preserving its public import
  surface, and made run-row plus run-event transitions atomic.
- Prevented two simultaneous workers from claiming the same paused run or
  opening duplicate active attempts.
- Marked interrupted active runs failed at startup so a restart cannot strand
  invisible work.
- Made backfill adoption and its ready marker one transaction, and repaired an
  older orphan marker instead of trusting it.
- Reconciled edited form identity fields by stable form timestamp so a corrected
  email or address does not reopen a delivered row as a new listing.
- Made roster replacement atomic and exact: removed contacts disappear, empty
  and duplicate sources do not silently preserve a stale snapshot, and no web
  result can overwrite submitted identity.
- Corrected the manual row tool so `--resume` requires a genuinely paused run
  and Google client construction failures are reported before use.
- Removed the unused web-agent lookup, stale watchdog, unused dependencies, and
  settings that advertised behavior no entry point could reach.

## Built, dormant, or specified but not connected

The static audit reports no high-confidence unused function in `src` or `tools`.
The genuinely dead agent lookup and watchdog were removed. The remaining items
are intentional compatibility state, partial capabilities, or unbuilt roadmap
work rather than hidden production behavior.

| Capability | Current truth |
|---|---|
| Synthetic property image | Only the policy enum and `ai_generated` audit column remain for compatibility. There is no generator, disclosure action, approval flow, or runtime call. |
| Automatic hero-photo discovery | Form-Drive, property-folder, brokerage-site, web, and MLS resolution are not connected. Gable uses one photo supplied in its owned Slack thread. |
| Brokerage URL cache | The required 24-hour cache belongs to the future web-photo resolver and is therefore not built. |
| Second-model consensus | Researched, not connected. It needs a representative disagreement and catch-rate evaluation before becoming another paid gate. |
| Saliency or focal crop retry | Not connected. Gable predicts crop loss and judges the render, but does not select a focal point and perform a bounded second render. |
| Run-event history viewer | Every transition is stored in `run_events`; no command yet explains one listing from that ledger. |
| Two-agent role placement | Listing and hosting roles parse, but there is no certified per-role object map. The runner stops before copying. |
| Generic missing-info answer persistence | A pre-build answer such as a missing phone number is not written back from free-form Slack. The human-owned form or contact workbook must be corrected, then `/gable run` rereads it. |
| Photo-host retention | Published derivatives are content-addressed, but no pruning or retention job exists. |
| Legacy salesperson columns | SQLite still carries `template`, `headshot_url`, and `brokerage_url`. Current contact sync supplies name, email, and phone; template routing ignores the old override, the Head Shots folder supplies portraits, and the configured brokerage website remains the fallback. |
| Pause and last-poll state | These are process-local operator controls. A service restart resumes configured polling and resets the displayed last-poll timestamp. |
