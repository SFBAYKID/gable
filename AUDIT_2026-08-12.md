# Flyer quality and template-triage audit

Date: 2026-08-12

## Executive finding

A well-structured template can now be rejected or warned about before Gable
creates a flyer, and a rendered flyer cannot be delivered when visual review is
unavailable, uncertain, or negative. That materially reduces corrections. It
does not make a defensible promise of a perfect flyer every time: current
multimodal models are probabilistic, Google Slides does not expose final
line-break layout, and a centre crop cannot know which part of every property
photo the photographer intended to preserve.

The dependable design is therefore layered:

1. exact source-object and frame geometry before mutation;
2. deterministic replacement, readback, and contact-data checks;
3. one composition-preserving photo fit against the measured frame;
4. a high-quality multimodal comparison of the supplied photo and Google's
   actual rendered pixels;
5. an editable Slides file and a human decision before anything leaves the
   building.

No single image model should replace the first three layers. A model is useful
for visible interactions that vector rectangles cannot express, such as a roof
hidden by a decorative mask. It is a worse source of truth for dimensions that
Google already returns exactly.

## Technology review

The review used current first-party documentation and the models visible to the
configured account on 2026-08-12.

- Google Slides exposes each editable page element's size and affine transform,
  which preserves the object identity needed for safe mutation. That makes the
  Slides object graph the authoritative measurement source for a Slides-native
  template. Child transforms are relative to their containing group, which is
  why fillable grouped text is refused rather than measured as though its local
  box were final. Sources: [Slides PageElement reference](https://developers.google.com/workspace/slides/api/reference/rest/v1/presentations.pages/pageElements#PageElement)
  and [Slides transform concepts](https://developers.google.com/workspace/slides/api/concepts/transforms).
- OpenAI's current model catalogue and latest-model guidance position the
  newest GPT-5 family for complex reasoning and multimodal work. The account
  can call `gpt-5.6-sol`, and a real Responses API vision request succeeded.
  Sources: [OpenAI model catalogue](https://developers.openai.com/api/docs/models)
  and [latest model guide](https://developers.openai.com/api/docs/guides/latest-model).
- The final visual gate now sends both the supplied property photo and the
  original-detail slide thumbnail through one Responses API request and
  requires strict schema output. It checks property fidelity, distortion,
  destructive crop, and layout together. It rejects incomplete, refused,
  malformed, or low-confidence responses rather than treating them as
  approval. Sources: [OpenAI vision guide](https://developers.openai.com/api/docs/guides/images-vision)
  and [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs).
- GPT Image 2 is used only when a real supplied photograph would need more than
  2x enlargement. The edit receives an exact pre-crop, preservation-only
  instructions, and a composition-distance fidelity test. It is never used to
  invent a property. Source: [GPT Image 2](https://developers.openai.com/api/docs/models/gpt-image-2).
- Gemini's current image-understanding models and Google Document AI's layout
  parser were considered. They are useful for raster documents, PDFs, and
  semantic extraction, but this product starts from an editable Google Slides
  object graph. Rasterising first would discard object IDs, exact transforms,
  and safe mutation targets, so neither improves the primary measurement path.
  They remain reasonable independent-evaluator options if a second-model gate
  is later justified. Sources: [Gemini models](https://ai.google.dev/gemini-api/docs/models),
  [Gemini image understanding](https://ai.google.dev/gemini-api/docs/image-understanding),
  and [Document AI layout parser](https://docs.cloud.google.com/document-ai/docs/layout-parse-chunk).

Conclusion: the strongest current architecture is exact Slides geometry plus a
frontier visual judge, not vision-only reconstruction. Gable is now using that
combination. The visual model is current and callable, but its verdict is a
fail-closed quality gate rather than evidence that perfection is guaranteed.

## Template triage now in runtime

`slides/preflight.py` measures the current Drive source before a copy is made.
For each listing it checks:

- exactly one slide and a measurable page;
- a recognised property-address field when the category needs one;
- unknown fillable-looking tokens;
- one safe hero-photo frame and its exact pixel dimensions;
- standalone replacement literals, preventing substring corruption;
- the actual listing values against each source text box's width, line count,
  type size, and weight;
- whether required shrinking would cross the 8 point readability floor; and
- crop loss between the supplied photo and the measured frame.

A structural or unreadable finding cannot be overridden. A usable but tight
value or large crop pauses with two choices: run the current design anyway or
update it and ask Gable to check again. Resuming the same Slack thread reloads
the current source file; it does not reuse a cached presentation or consume a
new run attempt.

The poller also watches `Generic Templates`. Its first scan silently records the
existing catalogue. A later file ID is treated as a new upload and receives a
capacity and structure check in a Gable-owned thread. If those pass, a
template-specific `gpt-5.6-sol` inspection checks visible clipping, overlap,
spacing, alignment, padding, and off-canvas elements while deliberately
ignoring intended placeholders and sample photos. Duplicate names and
PowerPoint files are refused precisely. An explicit recheck uses the same
native purple waiting state as mentions, flyer edits, and shared photos, with
the real stages set to measuring and then inspecting the updated template.

## Photo quality changes

The former Slack handoff cropped every image to the 4:5 slide and the placement
path cropped it again to the actual hero frame. Wide frames could never recover
the pixels removed by the first crop. Uploads now retain their aspect ratio and
composition until the source template's frame is known, then receive one crop.

The measured path is:

- apply EXIF orientation and strip metadata;
- downsize only an unnecessarily large edge at intake;
- calculate frame pixels from Slides geometry;
- warn before build when more than 30 percent would be outside the frame;
- fit locally for normal images;
- allow at most one GPT Image 2 enlargement beyond 2x;
- accept that enlargement only after composition fidelity passes;
- fall back to a local resize on any provider or fidelity failure; and
- inspect the finished Google render against the preserved human upload before
  delivery.

The final inspection receives the preserved human upload alongside the render.
That gives it evidence to reject an enlargement that still looks polished but
no longer depicts the same building or composition.

The original Slack upload is never overwritten. The database records AI
enhancement only when the model result is the derivative actually placed.

## Live verification performed

The production template path was exercised without posting to Slack or touching
the response Sheet:

1. The existing `Sold` source was copied into `Generic Templates` with a unique
   smoke-test name.
2. A temporary SQLite database adopted the one existing source and ran the same
   new-file detector used by the poller.
3. Exactly one new template was reviewed. It entered `needs_template` because
   its address section measured roughly 34 average characters against the safe
   certification target of 52.
4. A `finally` block moved only the smoke-test copy to Drive trash. A follow-up
   listing confirmed no active smoke-test copy remained.

The actual `Sold` Slides thumbnail was also sent through both strict visual
paths. The rendered-flyer prompt and the new placeholder-aware source-template
prompt each returned checked, confident, visually acceptable verdicts with no
reported problem. That proves the configured model, Responses payload, image
detail, schema, thumbnail download, and spend ledger work together. It is not
represented as an end-to-end certification of a filled production flyer.

The recoverable test command is:

```bash
.venv/bin/python tools/template_smoke_test.py --source Sold
```

## Bugs fixed in this audit

- Removed the double crop that irreversibly discarded a supplied photo before
  its template frame was known.
- Added source-versus-render visual comparison so a tidy flyer cannot hide a
  materially changed, distorted, or destructively cropped property photo.
- Raised the conservative vision reservation for the new two-image request so
  the hard spend ledger does not price it like the former one-thumbnail call.
- Added placeholder-aware visual review to new-template triage; geometry alone
  could not identify visible overlap, inconsistent spacing, or broken padding.
- Persisted each new-template verdict before posting it so a Slack outage
  retries only the stored message instead of spending on the same visual review
  every poll cycle.
- Added pre-build source measurement, including actual listing text and photo
  shape, before any Drive copy is created.
- Moved recognised-but-empty template fields into preflight; they now pause and
  name the missing value before a copy exists instead of relying on post-build
  placeholder detection.
- Made fillable text inside transformed groups a structural finding instead of
  pretending its child-relative size was an exact rendered capacity. Gable asks
  for that field to be ungrouped into its own text box before it builds.
- Corrected the readability warning to say 8 points or smaller; the fitting
  calculation clamps at 8 and could not truthfully claim a smaller exact size.
- Made names, email addresses, phone numbers, prices, and other identity fields
  single-line capacity checks; a tall box no longer hides the wrap problem the
  preflight is supposed to warn about.
- Connected an explicit template update or `run anyway` to a real same-run
  reload and rebuild; the previous conversational route did not perform it.
- Made `yes, run again` deterministically reload the updated Drive source, while
  only explicit `run anyway` or `use the current template as-is` wording accepts
  the current warning. Those opposite actions no longer depend on a model guess.
- Allowed an updated-template recheck even while the listing still has no
  photo, so template repair no longer deadlocks behind the later photo stage.
- Made unavailable and inconclusive visual inspection block delivery. It could
  previously degrade into a success path.
- Made failed Slides readback block delivery rather than silently pass the
  value audit.
- Made a failed agent-headshot replacement block delivery rather than leave a
  different agent's sample face on the flyer.
- Distinguished a headshot-free design from a failed replacement, so a valid
  template without that slot is not held back merely because the roster has a
  photo for the agent.
- Corrected repeated standalone replacements: Google may report several
  occurrences for one logical request, which was previously misread as an
  incomplete batch.
- Rejected malformed model booleans such as the string `false`; ordinary truthy
  coercion could have turned that into approval.
- Made a contradictory visual response that says the design passes while also
  naming a defect fail closed instead of trusting its top-level boolean.
- Joined split Responses text chunks before parsing; reading only the first
  chunk could turn valid structured output into an unavailable inspection.
- Cleared stale `ai_enhanced` state before every refit and records it only after
  the accepted derivative is published and verified.
- Made unsupported PowerPoint uploads visible to triage instead of silently
  filtering them out.
- Made a template recheck reevaluate current duplicate names; it could
  previously certify one file while the folder was still ambiguous.
- Removed raw HTTP codes from user-facing photo failures and kept review
  messages inside the listing's originating thread.
- Replaced false photo attribution with the neutral `slack_upload` provenance.
- Corrected a photo-handoff failure that still claimed the image had been
  fitted even though the new composition-preserving path had only prepared it.
- Kept Slack's native waiting state alive through the actual question, review
  result, or delivery post; three runner branches previously cleared it just
  before posting the outcome.
- Made generic pipeline failures state that processing failed and that nothing
  was sent as finished.
- Rejected the old `GABLE_DRY_RUN=true` switch at startup. It claimed isolation
  while still writing to Drive and Slack; conversation-only testing now uses
  `GABLE_POLL_ENABLED=false`.
- Removed stale hand-entered character budgets and hero object IDs after exact
  current-source measurement superseded them.
- Removed a numeric seam detector that had been measured unable to distinguish
  a pasted sky from an ordinary roofline or treeline.
- Removed unused runtime settings for Spaces, Anthropic, photo confidence,
  verification caching, description length, retry count, signing secrets, URL
  length, and an unconnected generation model. Their presence suggested
  behavior the process did not have.
- Corrected the connection checker to verify all three configured OpenAI models,
  including the real enlargement model, instead of an unused generation name.
- Removed an unwired token-cost calculator and model-price table. Runtime never
  ingested token usage and has always enforced the ceiling with conservative
  per-call reservations, so the calculator added false accounting precision.

## Built or specified but still not connected

The remaining gaps are explicit rather than silently advertised:

- **Synthetic property-photo generation:** the database retains the required
  `ai_generated` audit column and the policy enum retains compatibility values,
  but there is no generator, approval action, disclosure flow, or runtime call.
  Both generation-labelled settings are now rejected instead of silently
  advertising unavailable behavior.
- **Automatic hero-photo discovery:** there is no live form-photo, Drive-folder,
  brokerage-site, general-web, or MLS resolver. The runtime uses the single
  image Carmen or Chase supplies in the Gable-owned Slack thread.
- **24-hour brokerage photo cache:** this was specified for a future web-photo
  resolver, but no resolver exists, so no cache is connected.
- **Second-model visual consensus:** Gemini and Document AI are researched but
  not integrated. Adding them would increase cost and latency and still would
  not replace exact Slides geometry. It should be a measured reliability
  experiment, not a default assumption.
- **Automatic crop recovery:** the system warns before a destructive crop and
  catches a bad rendered crop, but it does not yet ask a model for a focal-point
  crop and retry automatically. Doing that safely requires a bounded crop plan,
  a second render, and proof that it improves real listing photos without
  moving the property off-centre.
- **Slash-command surface:** `AGENTS.md` specifies `/gable status`, `run`,
  `retry`, `templates`, `pause`, and `resume`, but the Bolt app registers no
  slash-command handlers. Thread-level status and the explicit updated-template
  rebuild work; the global command surface does not. The unused
  `store.paused_runs` query appears to have been built for this missing path.
- **Transition-history reader:** every state change is correctly appended to
  `run_events`, but no runtime or operator command reads that history yet. It is
  a real audit ledger, not dead storage, but the “explain this listing” view it
  enables has never been connected.

These gaps define the honest ceiling today. They do not prevent the core flow
requested here: a supplied photo, a well-structured template, measured triage,
same-thread repair, and fail-closed rendered inspection.
